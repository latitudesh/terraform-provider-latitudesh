# latitudesh_lks_kubeconfig (Ephemeral Resource)

Reads an LKS (Latitude Kubernetes Service) cluster's kubeconfig for the duration of a Terraform run. As an [ephemeral resource](https://developer.hashicorp.com/terraform/language/resources/ephemeral), it is never written to state or plan files. Requires Terraform 1.10 or later.

The cluster must be ready, which takes a node pool with nodes. For a cluster that already exists, read its id from [`latitudesh_lks_clusters`](../data-sources/lks_clusters.md) filtered on `status = "ready"`, as the example does. For a cluster created in the same configuration, reference the resource and order the read after its node pools:

```terraform
ephemeral "latitudesh_lks_kubeconfig" "new_cluster" {
  cluster_id = latitudesh_lks_cluster.example.id

  depends_on = [latitudesh_lks_node_pool.example]
}
```

If the read fails right after the cluster becomes ready, run the apply again.

## Example Usage

```terraform
# Reads a cluster's kubeconfig into memory for the duration of the run — never
# into state or a plan file. Requires Terraform 1.10 or later.
data "latitudesh_lks_clusters" "kubeconfig_source" {
  project = "<project-id-or-slug>"
  status  = "ready"
}

ephemeral "latitudesh_lks_kubeconfig" "example" {
  cluster_id = data.latitudesh_lks_clusters.kubeconfig_source.clusters[0].id
}
```

## Using it with the kubernetes provider

The resource exposes the kubeconfig document; pull fields out with [`yamldecode`](https://developer.hashicorp.com/terraform/language/functions/yamldecode):

```terraform
locals {
  # Ephemeral values are allowed in locals as long as the local itself is only
  # used somewhere ephemeral values are allowed — a provider block is.
  kubeconfig = yamldecode(ephemeral.latitudesh_lks_kubeconfig.example.kubeconfig)
}

provider "kubernetes" {
  host                   = local.kubeconfig.clusters[0].cluster.server
  cluster_ca_certificate = base64decode(local.kubeconfig.clusters[0].cluster["certificate-authority-data"])

  # Your cluster's document decides which of these two applies. Read it once
  # before committing either:
  #   terraform console
  #   > yamldecode(...).users[0].user
  client_certificate = base64decode(local.kubeconfig.users[0].user["client-certificate-data"])
  client_key         = base64decode(local.kubeconfig.users[0].user["client-key-data"])
  # token            = local.kubeconfig.users[0].user.token
}
```

Indexing `[0]` is safe only for a single-cluster document; resolve through `current-context` to be strict about it. To write the raw document to disk instead, use `local_sensitive_file` — never `local_file`.
