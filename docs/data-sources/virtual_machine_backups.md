# latitudesh_virtual_machine_backups (Data Source)

List [Latitude.sh](https://latitude.sh/) virtual machine backups, optionally scoped to one virtual machine and filtered by status. Results are newest first, so with `status = "Ready"` the first entry is the latest restorable backup and the natural input for `backup_id` on `latitudesh_virtual_machine`.

## Example Usage

```terraform
# Every Ready backup of one virtual machine, newest first.
data "latitudesh_virtual_machine_backups" "by_vm" {
  virtual_machine = "vm_..." # virtual machine ID
  status          = "Ready"
}

# The most recent Ready backup is backups[0]; it is what a new VM restores from.
output "latest_ready_backup_id" {
  value = length(data.latitudesh_virtual_machine_backups.by_vm.backups) > 0 ? data.latitudesh_virtual_machine_backups.by_vm.backups[0].id : null
}
```

## Schema

### Optional

- `status` (String) Only return backups with this status (`Creating`, `Ready`, `Failed`, or `Archived`; case-insensitive).
- `virtual_machine` (String) Virtual machine ID to scope the list to. When omitted, every backup in the team is listed.

### Read-Only

- `backups` (Attributes List) The matching backups, newest first. (see [below for nested schema](#nestedatt--backups))
- `id` (String) Synthetic identifier for this query: the `virtual_machine` filter (or `all`), followed by `/<status>` when a status filter is set.
