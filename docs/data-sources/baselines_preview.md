# latitudesh_baselines_preview (Data Source)

~> **Preview.** Available only to teams with the `baselines_api` feature flag. The shape of this data source may change before general availability.

Retrieve a [baseline](https://www.latitude.sh/) by `id` or `name`.

## Example usage

```terraform
resource "latitudesh_baselines_preview" "ubuntu_default" {
  name             = "ubuntu-default"
  description      = "Default baseline for all servers"
  target_type      = "all_servers"
  operating_system = "ubuntu_24_04_x64_lts"
  ssh_key_ids      = ["sshk_xxxxx"]

  disk_layout = [
    {
      role  = "os"
      count = 1
    },
    {
      role        = "storage"
      count       = 2
      raid_level  = "raid-1"
      filesystem  = "ext4"
      mount_point = "/data"
    },
  ]
}

data "latitudesh_baselines_preview" "by_name" {
  name = "ubuntu-default"
}
```

## Schema

### Optional

- `id` (String) Baseline ID to look up. Mutually exclusive with `name`.
- `name` (String) Baseline name to look up. Mutually exclusive with `id`.

### Read-Only

- `created_at` (String) Date the baseline was created.
- `description` (String) Description of the baseline.
- `disk_layout` (Attributes List) Expected disk layout. (see [below for nested schema](#nestedatt--disk_layout))
- `operating_system` (String) Slug of the operating system the baseline expects the server to run.
- `platforms` (List of String) Slugs of the plans this baseline applies to (only populated when `target_type` is `"platforms"`).
- `ssh_key_ids` (List of String) SSH key IDs the baseline expects on the server.
- `target_type` (String) Baseline target: `all_servers`, `custom`, or `platforms`.
- `user_data_id` (String) ID of the user data the baseline expects to run on first boot.

### Nested Schema for `disk_layout`

Read-Only:

- `raid_level` (String) RAID level for the group.
- `role` (String) Purpose of the disk group: `os`, `storage`, or `raw`.
