# latitudesh_elastic_ip_bgp (Resource)

Reserves a static public IPv4 `/32` in a site and announces it over iBGP from one or more servers. Because the servers announce the address themselves, it can be shared, failed over or load-balanced between them — the usual building block for a virtual IP in front of a cluster.

For an address that is simply routed to one server and moved between servers with an API call, use [`latitudesh_elastic_ip`](elastic_ip) instead. The two are different objects in the API and cannot be converted into each other.

## Requirements

- BGP must be enabled for the site. It is a per-site capability, not a per-team one.
- Every announcing server must be deployed with `bgp_ready = true` (see [`latitudesh_server`](server)) and live in the same site as the address.
- Up to 5 announcers per address by default. The cap is a team limit.

## Example usage

```terraform
# A BGP-mode Elastic IP is a /32 allocated in a site and announced over iBGP by
# one or more servers, so the address can be shared or failed over between them.
# Every announcer must be deployed with bgp_ready = true, in the same site as the
# address, and BGP must be enabled for that site.
resource "latitudesh_server" "bgp_announcer" {
  count = 2

  hostname         = "tf-bgp-announcer-${count.index}"
  operating_system = "ubuntu_24_04_x64_lts"
  plan             = "c2-small-x86"
  project          = latitudesh_project.project.id
  site             = "DAL"
  bgp_ready        = true
}

resource "latitudesh_elastic_ip_bgp" "vip" {
  project    = latitudesh_project.project.id
  site       = "DAL"
  server_ids = latitudesh_server.bgp_announcer[*].id
}

# The address each server announces from its loopback.
output "bgp_vip_address" {
  value = latitudesh_elastic_ip_bgp.vip.address
}

# The BGP neighbor to configure on each announcer — `neighbor` in BIRD,
# `peerAddress` in MetalLB.
output "bgp_neighbors" {
  value = {
    for session in latitudesh_elastic_ip_bgp.vip.bgp_sessions :
    session.server_id => session.peer_address
  }
}
```

Each server still has to run a BGP daemon and announce the address. `bgp_sessions[*].peer_address` is the neighbor to peer with, and the ASN is on `bgp_sessions[*].asn`:

```hcl
output "bird_config" {
  value = {
    for session in latitudesh_elastic_ip_bgp.vip.bgp_sessions : session.server_id => <<-EOT
      protocol bgp latitudesh {
        local as ${session.asn};
        neighbor ${session.peer_address} as ${session.asn};
        ipv4 { export filter { if net = ${latitudesh_elastic_ip_bgp.vip.address}/32 then accept; reject; }; };
      }
    EOT
  }
}
```

### Adding and removing announcers

Changing `server_ids` opens or closes that server's session in place — the address is not reallocated, so the VIP survives the change:

```hcl
resource "latitudesh_elastic_ip_bgp" "vip" {
  project    = latitudesh_project.project.id
  site       = "DAL"
  server_ids = [latitudesh_server.a.id, latitudesh_server.b.id, latitudesh_server.c.id]
}
```

Sessions are closed before new ones are opened, so swapping an announcer works even when the address is already at the session limit.

> **Note:** the API removes a session on its own when its server is deleted or recommissioned. That shows up as drift on the next refresh and the following plan re-opens it. If you are decommissioning a server for good, drop it from `server_ids` in the same change.

### Allocating without announcers

`server_ids` may be omitted to reserve the address first and announce it later:

```hcl
resource "latitudesh_elastic_ip_bgp" "reserved" {
  project = latitudesh_project.project.id
  site    = "DAL"
}
```

### Customizing timeouts

Override the default 15-minute timeouts per operation. Use `=` because `timeouts` is a nested attribute, not a block:

```hcl
resource "latitudesh_elastic_ip_bgp" "vip" {
  project    = latitudesh_project.project.id
  site       = "DAL"
  server_ids = [latitudesh_server.a.id]

  timeouts = {
    create = "20m"
    update = "20m"
    delete = "10m"
  }
}
```

### Required

- `site` (String) Site slug the address is allocated in (case-insensitive, e.g. `DAL`). BGP is enabled per site, and every announcing server must be in this same site. Changing it forces a new resource.

### Optional

- `project` (String) The project (ID or slug) that owns the Elastic IP. Optional here only if `project` is set on the provider block; one of the two is required. Changing it forces a new resource.
- `server_ids` (Set of String) Servers announcing this address over BGP. Each one must be deployed with `bgp_ready = true` and live in `site`. Omitting the attribute leaves whatever sessions exist untouched; set it to `[]` to close them all.

- `prefix_length` (Number) Prefix length of the allocated block (always `32` today)

## Import

BGP Elastic IPs are imported by ID. The announcing servers and their sessions are read back from the API, so `server_ids` does not need to be written first.

```sh
terraform import latitudesh_elastic_ip_bgp.vip ueip_XXXXXXXX
```

> **Note:** `project` comes back as the project ID. If your configuration refers to the project by slug, adjust it after importing — `project` forces a new resource, so a mismatch plans a replacement.
