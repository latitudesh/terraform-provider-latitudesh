# latitudesh_block_storage (Resource)

Creates and manages a persistent NVMe-TCP block storage volume on [Latitude.sh](https://latitude.sh/).

There is no update endpoint for volumes, so changing any attribute forces a new resource. Mapping the volume to a server or mounting it to a client are separate lifecycle operations not managed by this resource.

## Example Usage

```terraform
resource "latitudesh_project" "block_storage" {
  name              = "Block storage example"
  environment       = "Development"
  provisioning_type = "on_demand"
}

resource "latitudesh_block_storage" "example" {
  project    = latitudesh_project.block_storage.id
  name       = "app-data"
  region     = "ASH"
  size_in_gb = 100
}

data "latitudesh_block_storage" "by_id" {
  id = latitudesh_block_storage.example.id
}

data "latitudesh_block_storage" "by_name" {
  name    = "app-data"
  project = latitudesh_project.block_storage.id
}
```

## Schema

### Required

- `name` (String) Volume name. Changing this forces a new resource.
- `region` (String) Site slug where the volume is provisioned. Changing this forces a new resource.
- `size_in_gb` (Number) Volume size, in GB. Changing this forces a new resource.

### Optional

- `project` (String) The project (ID or slug) to create the volume in. Optional here only if `project` is set on the provider block; one of the two is required. Changing it forces a new resource.

### Read-Only

- `connector_id` (String) Connector identifier used to reach the volume over NVMe-TCP.
- `id` (String) Block storage volume identifier.
- `namespace_id` (String) NVMe namespace identifier assigned to the volume.
