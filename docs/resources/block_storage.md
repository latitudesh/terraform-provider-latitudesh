# latitudesh_block_storage (Resource)

Adds a persistent [block storage](https://www.latitude.sh/) volume to a project. The API has no volume update endpoint, so changing any input attribute (`name`, `project`, `region`, `size_in_gb`) replaces the resource.

## Example usage

```terraform
variable "project" {
  type    = string
  default = "proj_..."
}

resource "latitudesh_block_storage" "example" {
  project    = var.project
  name       = "example-volume"
  region     = "SAO" # site/region slug; not returned by the read API, see docs
  size_in_gb = 100
}

data "latitudesh_block_storage" "by_id" {
  id = latitudesh_block_storage.example.id
}

data "latitudesh_block_storage" "by_name" {
  project = var.project
  name    = latitudesh_block_storage.example.name
}

output "block_storage_id" {
  value = latitudesh_block_storage.example.id
}

output "block_storage_namespace_id" {
  value = latitudesh_block_storage.example.namespace_id
}
```

> **Note:** `region` is not returned by the volume read API, so it is never refreshed from state — it always reflects whatever was last applied in configuration. Getting it wrong does not surface as drift; it only shows up as a replace if you later change it.

> **Note:** Mounting the volume to a client (adding an NVMe initiator to its allow list) is a separate API lifecycle (`PostStorageVolumesMount`) that this resource does not manage; see `initiators` for the current allow list.

## Schema

### Required

- `name` (String) The volume name. Changing this forces a new resource (the API has no update endpoint).
- `region` (String) The region (site) slug where the volume is provisioned (e.g. SAO, ASH). Changing this forces a new resource. Not returned by the read API: it is not refreshed from state and must be kept in configuration, including after import (see the Import section).

### Optional

- `project` (String) The project (ID or slug) to create the volume in. Optional here only if `project` is set on the provider block; one of the two is required. Changing it forces a new resource.
- `size_in_gb` (Number) Size of the volume in GB. Defaults to 1500 if not set. Changing this forces a new resource.

### Read-Only

- `cluster_user` (String) Ceph cluster user used to connect to the volume. Returned only for dashboard-origin requests; null until the volume is provisioned.
- `connector_id` (String) Connector ID of the volume
- `created_at` (String) The timestamp for when the volume was created
- `id` (String) Block storage volume identifier
- `initiators` (Attributes List) NVMe initiators (clients) currently allowed to mount the volume. This resource does not manage mounts (see `PostStorageVolumesMount` in `sdk-coverage.yaml`); this reflects whatever is mounted out-of-band. (see [below for nested schema](#nestedatt--initiators))
- `keyring` (String, Sensitive) Cephx keyring secret used to connect to the volume. Returned only for dashboard-origin requests; null until the volume is provisioned.
- `namespace_id` (String) Namespace ID of the volume
- `volume_path` (String) Path of the volume inside the cluster. Returned only for dashboard-origin requests; null until the volume is provisioned.

## Import

You can import a block storage resource using either the CLI method or the [experimental import block](https://developer.hashicorp.com/terraform/language/import).

**CLI Import**

The `latitudesh_block_storage` resource can be imported by specifying the volume ID:

```sh
terraform import latitudesh_block_storage.example <VOLUME_ID>
```

> **Note:** Because `region` cannot be read back from the API, your configuration must already declare the volume's actual region before importing — the imported state cannot supply it, and Terraform will otherwise plan to replace the resource on the next apply.

**Import Block (Experimental)**

Terraform v1.5.0 and later supports the experimental import block, which allows you to define imports in your configuration.

```hcl
import {
  to = latitudesh_block_storage.example
  id = "<VOLUME_ID>"
}
```

Then run:

```sh
terraform plan -generate-config-out=generated_block_storage.tf
```

> **Note:** The import block feature is experimental and its syntax or behavior may change in future Terraform versions.
