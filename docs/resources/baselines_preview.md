# latitudesh_baselines_preview (Resource)

~> **Preview.** Available only to teams with the `baselines_api` feature flag. The shape of this resource may change before general availability.

A baseline records the configuration you expect your servers to be delivered with: target (all servers, a custom set, or specific platforms), operating system, SSH keys, user data, and disk layout. When a baseline targets platforms, the disk layout is validated server-side against the smallest of the selected platforms.

There is no update endpoint for baselines: any change to this resource replaces it.

## Example usage

```terraform
resource "latitudesh_baselines_preview" "ubuntu_default" {
  name             = "ubuntu-default"
  description      = "Default baseline for all servers"
  target_type      = "all_servers"
  operating_system = "ubuntu_24_04_x64_lts"
  ssh_key_ids      = ["sshk_xxxxx"]

  disk_layout = [
    {
      role  = "os"
      count = 1
    },
    {
      role        = "storage"
      count       = 2
      raid_level  = "raid-1"
      filesystem  = "ext4"
      mount_point = "/data"
    },
  ]
}

data "latitudesh_baselines_preview" "by_name" {
  name = "ubuntu-default"
}
```

## Schema

### Required

- `name` (String) Name of the baseline.
- `operating_system` (String) Slug of the operating system the baseline expects the server to run.
- `target_type` (String) Baseline target: `all_servers`, `custom` (a set of servers, when the plan is not yet known), or `platforms` (one or more specific platforms). When `platforms`, set `platforms` to the plan slugs it applies to.

### Optional

- `description` (String) Description of the baseline.
- `disk_layout` (Attributes List) Expected disk layout. When the baseline targets specific platforms, this is validated server-side against the smallest of the selected platforms. (see [below for nested schema](#nestedatt--disk_layout))
- `platforms` (List of String) Slugs of the plans this baseline applies to. Required when `target_type` is `"platforms"`.
- `ssh_key_ids` (List of String) SSH key IDs the baseline expects on the server.
- `user_data_id` (String) ID of the user data the baseline expects to run on first boot.

### Read-Only

- `created_at` (String) Date the baseline was created.
- `id` (String) Baseline identifier.

### Nested Schema for `disk_layout`

Required:

- `count` (Number) Number of disks in the group.
- `role` (String) Purpose of the disk group: `os`, `storage`, or `raw`.

Optional:

- `filesystem` (String) Filesystem to format the group with. Only valid for the `storage` role. Only `ext4` is currently accepted by the SDK.
- `mount_point` (String) Where the group is mounted, e.g. `/data`. Required for the `storage` role.
- `raid_level` (String) RAID level for the group: `raid-0` or `raid-1`. Only valid for the `os` and `storage` roles.
