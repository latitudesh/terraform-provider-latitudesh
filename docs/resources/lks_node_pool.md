# latitudesh_lks_node_pool (Resource)

The LKS node pool resource allows you to create and manage node pools within an LKS (Latitude Kubernetes Service) cluster. Every pool, the first one included, is one of these, so each scales, upgrades and is destroyed without touching the cluster. See [Node Pools](https://www.latitude.sh/docs/lks/node-pools) for how node pools work.

`node_count` scales the pool in place; `cluster_id`, `plan` and `max_pods_per_node` force a new resource. Omit `kubernetes_version` and the pool follows the cluster's Kubernetes version — a cluster upgrade reaches the pool on the **next** apply; reference the cluster's `kubernetes_version` to upgrade both in the same apply, or set a literal version to pin the pool. A pool can never run a version newer than the control plane, and any version change recycles the pool's nodes.

Keep at least one pool in the cluster free of `NoSchedule` and `NoExecute` taints, or the cluster never becomes ready: keep a general-purpose pool and taint the specialized ones, as the example does.

## Example Usage

```terraform
data "latitudesh_lks_sites" "for_pool" {}

data "latitudesh_lks_versions" "for_pool" {}

locals {
  pool_site = data.latitudesh_lks_sites.for_pool.sites[0].slug
}

data "latitudesh_lks_plans" "for_pool" {
  site = local.pool_site
}

resource "latitudesh_project" "lks_node_pool" {
  name = "lks-node-pool-example"
}

resource "latitudesh_lks_cluster" "node_pool_example" {
  project            = latitudesh_project.lks_node_pool.id
  name               = "example-cluster"
  site               = local.pool_site
  kubernetes_version = data.latitudesh_lks_versions.for_pool.default_version
}

# Untainted general-purpose pool; every cluster needs at least one.
resource "latitudesh_lks_node_pool" "general" {
  cluster_id = latitudesh_lks_cluster.node_pool_example.id
  node_count = 1
  plan       = keys(data.latitudesh_lks_plans.for_pool.stock)[0]

  labels = {
    "workload" = "general"
  }
}

# A tainted pool is reserved for workloads that tolerate the taint. Referencing
# the cluster's kubernetes_version keeps the pool on the control-plane version.
resource "latitudesh_lks_node_pool" "gpu" {
  cluster_id         = latitudesh_lks_cluster.node_pool_example.id
  node_count         = 2
  plan               = keys(data.latitudesh_lks_plans.for_pool.stock)[0]
  kubernetes_version = latitudesh_lks_cluster.node_pool_example.kubernetes_version

  labels = {
    "workload" = "gpu"
  }

  taints = [{
    key    = "dedicated"
    value  = "gpu"
    effect = "NoSchedule"
  }]

  # Bare metal nodes take a while to provision.
  timeouts = {
    create = "90m"
    update = "90m"
    delete = "30m"
  }
}
```

## Schema

### Required

- `cluster_id` (String) ID of the cluster the pool belongs to. Changing it forces a new resource.
- `node_count` (Number) Number of nodes in the pool. Changing it scales the pool in place.
- `plan` (String) Plan the pool's nodes are provisioned from, as listed by `latitudesh_lks_plans`. Pick one with stock at the cluster's site. Changing it forces a new resource.

### Optional

- `description` (String) Optional description, up to 200 characters. It cannot be removed once set; change it instead.
- `kubernetes_version` (String) Kubernetes version for the pool's nodes, from `latitudesh_lks_versions`. Omit it and the pool follows the cluster's version, with a cluster upgrade reaching the pool on the next apply; set it to pin the pool. It can never be newer than the control plane, and any version change recycles the pool's nodes.
- `labels` (Map of String) Kubernetes labels applied to every node in the pool, up to 50. Keys under `kubernetes.io`, `k8s.io`, `cluster.x-k8s.io` and `lks.latitude.sh` are reserved.
- `max_pods_per_node` (Number) Maximum Pods per node, between 16 and 500. Defaults to 110. Changing it forces a new resource.
- `name` (String) Display name for the pool. Generated when omitted.
- `taints` (Attributes Set) Kubernetes taints applied to every node in the pool, up to 50; each `(key, effect)` pair must be unique.

Keep at least one pool in the cluster free of `NoSchedule` and `NoExecute` taints, or the cluster never becomes ready. (see [below for nested schema](#nestedatt--taints))
- `timeouts` (Attributes) (see [below for nested schema](#nestedatt--timeouts))
- `type` (String) Node type. `bare_metal` is the only value accepted today. Changing it forces a new resource.

### Read-Only

- `created_at` (String) Timestamp when the pool was created.
- `id` (String) Node pool identifier.
- `message` (String) Human-readable detail behind the current `status`.
- `mode` (String) Pool mode.
- `platform_version` (String) Platform (LKS controller) version managing this pool.
- `ready_nodes` (Number) Nodes currently ready. Null when the platform does not report it.
- `reason` (String) Status reason code reported for the pool.
- `status` (String) Pool status, e.g. `provisioning` or `ready`.
- `updated_at` (String) Timestamp when the pool was last updated.

Required:

- `effect` (String) Taint effect: `NoSchedule`, `PreferNoSchedule` or `NoExecute`.

- `value` (String) Taint value.


<a id="nestedatt--timeouts"></a>
### Nested Schema for `timeouts`

Optional:

- `create` (String) Budget for the entire create: the pool settling (the platform reporting no operation in progress, and ready_nodes reaching node_count when it reports one), then the cluster settling on the new nodes — normally "ready". The second part only warns when it runs out. Bare metal, so allow for a real deploy. Default: 60 minutes.
- `delete` (String) Timeout for the pool to be fully removed. Default: 30 minutes.
- `update` (String) Timeout for a scale or version change to settle. A scale and a version change in one apply are two sequential operations, each waited on, within this one budget; if the scale uses it up, the version change is not started and the next apply picks it up. Default: 60 minutes.

## Import

A node pool is imported with its cluster ID and its own ID, separated by a colon.

**CLI Import**

```sh
terraform import latitudesh_lks_node_pool.example <LKS_CLUSTER_ID>:<NODE_POOL_ID>
```

**Import Block (Experimental)**

```hcl
import {
  to = latitudesh_lks_node_pool.example
  id = "<LKS_CLUSTER_ID>:<NODE_POOL_ID>"
}
```

Then run:

```sh
terraform plan -generate-config-out=generated_lks_node_pool.tf
```
