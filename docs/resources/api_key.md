# latitudesh_api_key (Resource)

The API key resource allows you to create and manage API keys within your [Latitude.sh](https://latitude.sh/) account.

> **Note:** The full token is only returned by the API when the key is created. That value is written to `token` in Terraform state, so **the state file itself becomes sensitive** for as long as this resource exists — protect it accordingly (remote state encryption, restricted access, etc.).

## Example usage

```terraform
resource "latitudesh_api_key" "ci" {
  name       = "ci-deploy-key"
  read_only  = false
  allowed_ips = ["203.0.113.10/32"]
}

data "latitudesh_api_key" "ci" {
  name = latitudesh_api_key.ci.name
}
```

## Schema

### Required

- `name` (String) Name of the API key

### Optional

- `allowed_ips` (List of String) List of allowed IP addresses or CIDR ranges (e.g., "192.168.1.100", "10.0.0.0/24") that may use this API key. Unset means no IP restriction.
- `read_only` (Boolean) Whether the API key is read-only. Read-only keys can only perform GET requests.

### Read-Only

- `api_version` (String) The API version associated with this API key.
- `created_at` (String) The timestamp for when the API key was created.
- `id` (String) API key identifier
- `last_used_at` (String) The last time a request was made to the API using this API key.
- `token` (String, Sensitive) The full API key token. Only returned by the API when the key is created; **this value lands in Terraform state**, so treat the state file as sensitive.
- `token_last_slice` (String) The last 5 characters of the token, safe to display for identification.
- `updated_at` (String) The timestamp for the last time the API key was updated.
- `user_email` (String) The email of the user that owns this API key.
- `user_id` (String) The ID of the user that owns this API key.

## Import

You can import an API key resource using either the CLI method or the [experimental import block](https://developer.hashicorp.com/terraform/language/import).

**CLI Import**

The `latitudesh_api_key` resource can be imported by specifying the API key ID:

```sh
terraform import latitudesh_api_key.ci <API_KEY_ID>
```

> **Note:** The API has no single-item read for API keys; import (and every subsequent refresh) lists all keys and matches by ID. Because the full token is only ever returned on create, `token` is **not** populated by import and remains empty in state until the next `terraform apply` that recreates the key.

**Import Block (Experimental)**

Terraform v1.5.0 and later supports the experimental import block, which allows you to define imports in your configuration.

```hcl
import {
  to = latitudesh_api_key.ci
  id = "<API_KEY_ID>"
}
```

Then run:

```sh
terraform plan -generate-config-out=generated_api_key.tf
```

> **Note:** The import block feature is experimental and its syntax or behavior may change in future Terraform versions.
