# latitudesh_api_key (Resource)

Creates and manages an [API key](https://www.latitude.sh/dashboard/api-keys) tied to the current user account.

## Example usage

```terraform
resource "latitudesh_api_key" "ci" {
  name        = "ci-deploy-key"
  read_only   = false
  allowed_ips = ["203.0.113.10", "198.51.100.0/24"]
}

data "latitudesh_api_key" "by_id" {
  id = latitudesh_api_key.ci.id
}

output "ci_api_key_token" {
  value     = latitudesh_api_key.ci.token
  sensitive = true
}

output "ci_api_key_last_slice" {
  value = data.latitudesh_api_key.by_id.token_last_slice
}
```

> **Note:** `token` is only ever populated by the create call — the Latitude.sh API has no way to retrieve a previously issued token. It is stored in Terraform state; treat state for this resource as sensitive. Rotating the token (which invalidates the previous one) is not something this resource does on your behalf: changing `name`, `read_only`, or `allowed_ips` updates those settings in place without touching the token.

## Schema

### Required

- `name` (String) Name of the API key

### Optional

- `allowed_ips` (List of String) List of allowed IP addresses or CIDR ranges (e.g. `192.168.1.100`, `10.0.0.0/24`) that may use this API key. An empty list means no restriction.
- `read_only` (Boolean) Whether the API key is read-only. Read-only keys can only perform GET requests. Defaults to `false`.

### Read-Only

- `api_version` (String) The API version associated with this API key.
- `created_at` (String) The timestamp for when the API key was created.
- `id` (String) API key identifier
- `last_used_at` (String) The last time a request was made to the API using this key.
- `token` (String, Sensitive) The full API key token. Only ever returned by the create call — the read API never returns it, so it is preserved from state on every subsequent read and is null after import.
- `token_last_slice` (String) The last 5 characters of the token, safe to display for identification purposes.
- `updated_at` (String) The timestamp for the last time the API key was updated.
- `user_email` (String) The email of the user that owns this API key.
- `user_id` (String) The identifier of the user that owns this API key.

## Import

You can import an API key resource using either the CLI method or the [experimental import block](https://developer.hashicorp.com/terraform/language/import).

**CLI Import**

The `latitudesh_api_key` resource can be imported by specifying the API key ID:

```sh
terraform import latitudesh_api_key.ci <API_KEY_ID>
```

> **Note:** The read API never returns the token, so `token` is null after import.

Terraform v1.5.0 and later supports the experimental import block, which allows you to define imports in your configuration.
