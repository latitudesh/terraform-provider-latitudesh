# latitudesh_virtual_machine_power (Action)

Runs a power action on a [Latitude.sh](https://latitude.sh/) virtual machine: `power_on`, `power_off`, or `reboot`.

The `latitudesh_virtual_machine` resource has no attribute describing power state, so these operations have no declarative home. The action is how you drive them from Terraform: nothing about desired state changes, and invoking it never drifts the resource.

~> **Requires Terraform v1.14 or later.** Actions are not available on earlier CLI versions.

## Example usage

```terraform
resource "latitudesh_virtual_machine" "app" {
  name    = "app-01"
  site    = "ASH"
  plan    = "vm-small"
  project = latitudesh_project.project.id
}

# Run it on demand, with no resource change to hang it off:
#
#   terraform apply -invoke=action.latitudesh_virtual_machine_power.reboot
#
# A reboot returns as soon as the API accepts it: a restart ends at the status
# the machine started from, so there is nothing to wait on.
action "latitudesh_virtual_machine_power" "reboot" {
  config {
    virtual_machine_id = latitudesh_virtual_machine.app.id
    power_action       = "reboot"
  }
}

# power_on and power_off do wait: the action blocks until the machine reports
# the status it drives it to ("Stopped" here). Set wait_for_status = false to
# return as soon as the API accepts the request instead.
action "latitudesh_virtual_machine_power" "power_off" {
  config {
    virtual_machine_id = latitudesh_virtual_machine.app.id
    power_action       = "power_off"
  }
}

# Or trigger it during a normal apply from something that tracks *when* to act.
variable "reboot_generation" {
  description = "Bump to reboot latitudesh_virtual_machine.app on the next apply."
  type        = number
  default     = 1
}

resource "terraform_data" "reboot_generation" {
  input = var.reboot_generation

  lifecycle {
    action_trigger {
      events  = [after_update]
      actions = [action.latitudesh_virtual_machine_power.reboot]
    }
  }
}
```

Invoke it directly, outside of any resource change:

```sh
terraform apply -invoke=action.latitudesh_virtual_machine_power.reboot
```

## Schema

### Required

- `power_action` (String) The power action to run: `power_on`, `power_off`, or `reboot`.
- `virtual_machine_id` (String) The ID of the virtual machine to act on.

### Optional

- `wait_for_status` (Boolean) Wait until the virtual machine reports the status the action drives it to: `Running` for `power_on`, `Stopped` for `power_off`. Defaults to `true`; set to `false` to return as soon as the API accepts the action. Has no effect for `reboot`: a restart ends at the status it started from, so there is no target a wait could distinguish.
- `wait_timeout` (String) How long to wait for the target status, as a Go duration (for example `5m`). Defaults to `10m`. Ignored when `wait_for_status` is `false` and for `reboot`.

## Behavior

- **`wait_for_status` defaults to `true`**, so `power_on` blocks until the machine reports `Running` and `power_off` until it reports `Stopped`, failing if it lands in `Failed`. Status changes are streamed as progress events while it waits. The reported status is pushed by event watchers, so it typically settles within seconds — but the first polls may still read the pre-action status.
- **`reboot` returns as soon as the API accepts it.** A restart tears the instance down and brings it back to the status it started from, so there is no target a wait could distinguish from "never went down". `wait_for_status` and `wait_timeout` have no effect for it, and setting them raises a config warning.
- **The action does not update Terraform state.** A virtual machine powered off through this action still satisfies its `latitudesh_virtual_machine` resource on the next plan.
